# GitHub and GitLab Writing Language

Write every user-facing text that you create or edit on GitHub or GitLab in English. This includes pull-request and merge-request titles, descriptions, summaries, general comments, inline review comments, review submissions, replies, resolution or follow-up notes, issue comments, release text, and other free-form remote fields. Apply this rule regardless of the conversation language or the tool used (`gh`, `glab`, an API, MCP, or the browser). Preserve exact identifiers, code, commands, URLs, and required quotations.

Immediately before every GitHub or GitLab write, run a mandatory language gate over every outgoing free-form text field. If prose contains Cyrillic characters or is not written in English, do not submit it: translate the prose to English, then inspect the final payload again. Code, exact quotations, identifiers, commands, and URLs may retain their required original form, but surrounding authored prose must remain English. Do not treat a Russian-language user request, draft, repository discussion, or source text as permission to publish Russian prose. This gate is required before CLI execution, API or MCP mutation, and the final submit action in a browser.
